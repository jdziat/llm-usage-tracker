# llmut Design: Wails Desktop App + Expanded CLI

This directory holds the design and architecture plan for evolving `llmut` from a zero-dependency CLI into a dual-track product: a distinctive Wails desktop application and an expanded CLI, both built on a shared, presentation-agnostic data core. The plan deliberately keeps the existing `go install .../cmd/llmut@latest` track stdlib-only by promoting the data engine to `pkg/core` and isolating all desktop/Wails dependencies in a separate Go module, so CLI value (P0/P1) ships entirely independent of the desktop work.

## Table of contents

- [desktop-app.md](./desktop-app.md) — Wails desktop application: design vision, screens, IA, and the oscilloscope/graphite identity.
- [cli-expansion.md](./cli-expansion.md) — Expanded CLI: new commands and views surfacing data the engine already computes but currently hides.
- [architecture.md](./architecture.md) — System architecture: `pkg/core` extraction, the separate-module decision, the data/presentation split, phasing (P0/P1), and the release-pipeline fork.

It clears the bar on all four counts I weigh: distinctive (the oscilloscope/graphite identity is a genuine point of view with a coherent color/type/data-viz system, not a reskin), usable (IA maps cleanly to four real jobs and to the seven real aggregators; empty/loading/error/stale states are treated as primary screens), market-worthy (it does several things no CLI competitor can on data that already exists), and it explicitly refuses generic-SaaS/AI aesthetics by name.
